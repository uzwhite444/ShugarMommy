# База данных Sugar Mommy

Все скрипты выполняются одинаково: **Supabase → SQL Editor → вставить весь файл → Run**.
Каждый файл безопасно запускать повторно.

## Если база уже работает (обычный случай)

Обновления `08`, `09` и `10` уже применены — файлы оставлены **как история**.

`08_hardening_v3.sql` намеренно закрыт от повторного запуска: он содержит
дореформенную `bookings_antiflood()` (лимит заявок обходился коротким номером),
и повторный прогон вернул бы эту дыру. Для установки с нуля он не нужен —
всё его содержимое входит в `setup-all.sql`.

**Нужно выполнить один раз:** `11_cancel_by_code.sql` — отмена записи теперь
требует код заявки, а старая функция `cancel_booking(телефон, дата)` удаляется.
Пока файл не выполнен, отмена на сайте честно отвечает «позвоните нам».
Пока файл не выполнен, старая дыра открыта: чужую запись можно снять,
зная только номер телефона и дату.

**Затем — цена на сервере, ТРИ шага и именно в этом порядке:**

| Шаг | Что делать | Почему так |
|-----|------------|-----------|
| 1 | Выполнить `12_server_pricing.sql` | Появляется `create_booking()`. Старый сайт продолжает работать: прямая вставка ещё разрешена, простоя нет |
| 2 | Выложить новый сайт и сделать на нём пробную запись | Новый сайт пишет через `create_booking()`; проверяем, что запись дошла до админки |
| 3 | Выполнить `13_lock_anon_insert.sql` | Прямая вставка закрывается, цену больше нельзя прислать с сайта |

Если поменять шаги 1 и 3 местами — сайт перестанет сохранять заявки, поэтому
файл `13` сам проверяет, что через новую функцию уже кто-то записался, и
отказывается выполняться раньше времени.

## Прайс в базе — копия src/data.ts

Цены, скидки и сеты правит человек **только** в `src/data.ts`. SQL из него
порождается: `npm run pricing:sql` перезаписывает `12_server_pricing.sql` и
блок внутри `setup-all.sql`. Проверка `npm run pricing:check` (входит в
`npm run build`) падает, если сгенерированный SQL отстал от `src/data.ts`.

**После каждой правки цен: перегенерировать, закоммитить И выполнить
обновлённый `12_server_pricing.sql` в Supabase.** Иначе сайт покажет одну
цену, а база запишет другую — сайт напишет об этом в консоль браузера
(«Цена разошлась…»), но клиентка увидит только число с экрана.

## Если база создаётся с нуля

Строго в этом порядке:

| № | Файл | Что делает |
|---|------|-----------|
| 1 | `setup-all.sql` | Заявки, права доступа, уведомления в Telegram, занятость слотов, отмена записи, прайс и расчёт цены на сервере |
| 2 | `07_reminders.sql` | Напоминание клиентке за час до визита + планировщик каждые 5 минут |
| 3 | `credentials.local.sql` | Токен бота и chat_id (создайте из `credentials.example.sql`) |

Файлы `08_hardening_v3.sql`, `09_visit_duration.sql`, `10_antiflood_fix.sql`,
`11_cancel_by_code.sql`, `12_server_pricing.sql` и `13_lock_anon_insert.sql`
при установке с нуля **не нужны** — всё, что в них есть, уже входит в
`setup-all.sql`.

## Ключи Telegram

Реальный токен в репозиторий не попадает: `credentials.local.sql` закрыт в `.gitignore`.
Шаблон — `credentials.example.sql`, там же написано, где взять токен и chat_id.

## Кто такой админ

Доступ к панели `#/admin` привязан к одному аккаунту Supabase по его uid —
функция `is_admin()` в начале `setup-all.sql`. Чтобы сменить админа: заведите
пользователя в **Authentication → Users**, скопируйте его UID, впишите в `is_admin()`
и выполните файл ещё раз.

Регистрация новых пользователей должна оставаться **выключенной**
(Authentication → Providers → Email → «Allow new users to sign up»). Это второй
рубеж: даже если кто-то зарегистрируется, к данным клиенток он не получит доступа.

## Обработчик бота

`functions/telegram-webhook/` — Edge Function, принимает нажатие «Старт» в боте
и привязывает Telegram клиентки к её записи, чтобы прислать напоминание.

Развёртывание:

```bash
npx supabase functions deploy telegram-webhook --project-ref <ref> --no-verify-jwt
```

Ей нужны два секрета (Project Settings → Edge Functions → Secrets):
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET`. Без второго функция намеренно
не запускается — иначе её мог бы вызвать кто угодно.
